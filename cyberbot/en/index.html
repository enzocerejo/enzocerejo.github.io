Chapter 1

Context and goals

The starting point

Cyber is a Discord bot created by Enzo Cerejo, a student in BTS CIEL (Cybersecurity, IT and Networks, Electronics), IT and Networks option. The project came from a simple observation: a Discord server often stacks five or six different bots (one for tickets, one for moderation, one for levels, one for giveaways…). Each has its own permissions, its own dashboard, its own outages.

The idea: a single free bot that replaces all the others, plus a learning module to revise networking at CCNA level, which fits Enzo's training.

The goals

Goal What it means in practice
All-in-one Moderation, automod, tickets, levels, giveaways, verification, temporary voice channels, roles…
Modular Each server only turns on what it needs (Community and Academy modules)
Educational CCNA lessons, quizzes, glossary, daily challenge, network tools
Easy to configure A web panel in the style of MEE6, with Discord login
Safe No published secrets, minimal permissions, protected panel, personal data under control
Professional Public website, domain name, legal pages, visual identity, preparation for Discord verification

The long-term vision: "cartridges"

Enzo summed up his vision like this: a server asks for a custom module, Enzo builds it, then gives the server a unique ID. The administrator enters it in the panel ("Add a module") and Cyber installs the module, like the cards inserted into Baymax in Big Hero 6.

At the time of writing, this feature is announced as "Coming soon" in the panel and in the bot's bio: it is not coded yet. The Community and Academy modules, however, can be turned on per server.

Working method

The project was carried out with the help of Claude (Anthropic), used as developer and tutor:

  • Enzo acts as project lead and system administrator: he defines the requirements, tests every version on his servers, configures the infrastructure (domain name, Cloudflare DNS, Discord developer portal, GitHub, hosting provider) and approves the security choices.
  • Claude writes the code, explains every concept in French, carries out the audits and writes the step-by-step guides.

The rules set from the start:

  1. Never read, display or publish the .env file (bot token, secrets).
  2. Always test before delivering (node src/check.js checks every command).
  3. Keep a backup of every modified file.
  4. Explain simply what changes and what to do next (restart DEMARRER.bat, publish with PUBLIER.bat).

BTS CIEL skills involved

  • Networking: DNS (A, CNAME, TXT, SPF, DMARC records), ports, NAT, IPv4/IPv6, tunnels, HTTPS/TLS.
  • Cybersecurity: secret management, least privilege, multi-factor authentication, audits, OWASP (XSS, CSRF, injections), GDPR.
  • Systems: Linux hosting in a container (Pterodactyl/Docker), Windows scripts (.bat), backups and restore.
  • Development: Node.js, Discord API, Express, HTML/CSS/JS, Git and GitHub.
  • Project management: versions, prioritisation, documentation, dealing with a hosting provider (support tickets).

Project log

This chapter is the chronological account of the project: what was done, the problems encountered (technical and human), how they were solved and what I learned from them. Times are Paris time.

Days 1 and 2 · 25 and 26 October: Cyber is born

It all starts in a first conversation with Claude, titled "Custom Discord bot". My first sentence: "Can you help me create my own Discord bot? The code and everything?", to test it on a server where I am an administrator.

The specification

  • 🛠️ My first answers set the course: useful commands, moderation, welcome messages and roles, embeds, account information, and, as a nod to the homelab, an IP ping that gives away no sensitive information. For the language: "pick the most efficient one for heavy use" (it will be Node.js with discord.js).
  • 💡 The ambition grows very quickly: "I'd like to replace all the commands of all the other bots", "I want loads of commands, really loads". That is how the goal "one bot instead of MEE6, Carl-bot, Dyno and Ticket Tool" was born.

The logo

  • ⚠️ Human problem: I ask for a logo "bright pastel red that looks scary, like the Kali Linux dragon but without looking like it", then "more like a dragon". Claude does not generate images.
  • 💡 Solution: "worst case, write me a prompt and I'll ask a specialised AI". This method will be used for all the visuals (chapter 10). The final logo ends up being a red demon mask, which I generated myself.

Step by step in the Discord portal

  • ⚠️ "I already added the app to the server but it doesn't show as a BOT." 💡 The application had been invited without the bot scope: the invite link must be generated with the right scopes (bot and applications.commands).
  • ⚠️ Human problem: "Do you want me to go to CSC and give you access? How? MPC server?" I didn't know how to let Claude work on my PC. 💡 Claude wrote the files itself into a folder on my PC, then gave me a single script to run: DEMARRER.bat.
  • ⚠️ Human and security problem: I pasted the bot token straight into the conversation, then refused to change it ("nobody will have the conversation"). 🧠 I understood later that a secret that has been shared must be treated as compromised: all secrets were regenerated on 28 October (chapter 8). That is also where rule no. 1 of the project comes from: the .env is never read, displayed or published.

The first versions (v1.0 and v1.1)

  • 🛠️ v1.0: 20 commands (moderation, information, roles, polls, embeds), welcome messages, auto-role, log channel. From the start, /pingip refuses private addresses so it cannot be used to scan my own network.
  • 🛠️ v1.1: levels, automod, tickets, giveaways, verification, temporary voice channels, network tools. I also ask "where exactly is the bot's folder, how do I start it, and the list of all the commands with what they do".
  • ⚠️ Discord rejects /panelroles: a required option was placed after an optional one. 💡 Order fixed, and the check.js verification script now checks this rule for every command. "It works!"
  • 💡 My tester feedback: I remove /8ball and /dire ("don't like them"), and ask for many more jokes and a more complete /userinfo.
  • ⚠️ On the portal's Verification Qualifications page, I discover that terms of service and a privacy policy are required. 💡 We put it off: verification is only mandatory from 75 servers (it will be prepared on the 28th, chapter 9).

Hosting the bot and creating the website (v1.2)

  • ⚠️ Misconception: "Can I host the bot on GitHub, like my portfolio?" 💡 No: GitHub Pages only serves static pages. It is perfect for the website, but the bot must run on a machine that is always on. Plan: the website on GitHub Pages (free and secure), the bot on my PC for now, then on my own machine later.
  • 🛠️ The showcase website is born, first at enzocerejo.github.io/cyber, with the logo, banner and background I had prepared.
  • ⚠️ The images didn't show online: the assets folder had never been sent to GitHub, and I had to copy everything by hand after every change. 💡 Creation of PUBLIER.bat, which publishes the whole folder with Git in one double-click.
  • ⚠️ After an update, the browser showed the new HTML with the old CSS. 💡 "Cache-busting" version numbers are now added automatically to every file.
  • 🛠️ Visual redesign at my request: no more banner or background image ("let your imagination run"), animated network background, "glitch" title, animated Discord demo. I also remove my email from the site: a contact will come with a domain name.
  • ⚠️ "Not done properly here, redo it": part of the site was only half styled. Then "mod logo bug": the shield icon on the Moderation card jumped to the edge on hover. 💡 Both fixed (the icon was taking the full width of the card).
  • 💡 My question: why not build the panel without the server right now, just to have the visuals ready before Christmas? Result: a preview panel on the website, with the real Discord login, fake channels and a demo mode without an account.
  • ⚠️ "Invalid OAuth2 redirect_uri" when clicking "Log in with Discord". 💡 Two causes: index.html in the address, and "Cyber" versus "cyber" (GitHub respects capitals, Discord compares character by character). The address is now normalised.
  • 🧠 An honest question I asked that evening: "Can a bot entirely coded by an AI really be used without worry?" The answer: yes, if it is properly supervised: tests, audits, no sensitive data, and someone who understands what is delivered. That guided the rest of the project.
  • 💡 On the hardware side, I am already talking about future hosting: my father offers to swap his Raspberry Pi 5 8 GB kit for a Pi 5 2 GB. I keep the idea for Christmas (chapter 7).

The two modules (v1.3)

  • 💡 My idea: "two parts that can be combined or work independently", the community part (moderation, tickets…) and a cyber part that explains "what firewalls, routers… are, really complete". The choice must be "a simple checkbox or a command". The level: CCNA, with the three modules of the curriculum (ITN, SRWE, ENSA), and an AI that answers questions as long as it's about IT.
  • 🛠️ Result: the Community and Academy modules, 47 lessons, /quiz, /glossaire, /port, /osi, /cisco, the daily challenge and /ia (limited to 5 questions per hour per person).
  • ⚠️ The commands only appeared on one server: they were registered on a fixed server ID. 💡 Automatic registration on all the bot's servers, and as soon as it joins a new one.
  • 🧠 "Is it optimised if one day it's on 150,000 servers?" Honest answer: it's the right method for development, but in production it will need global commands, then mandatory sharding from 2,500 servers and a real database (chapter 12).

How it works inside

  • One command = one file in src/commands/<category>/. Each file exports its definition (data), its execution (execute) and, if needed, the handling of its buttons and autocomplete.

  • Scheduler (scheduler.js): reminders, end of giveaways, daily challenge, backups. A lock prevents two runs at the same time.
  • Components V2: since v1.7, a module automatically converts every embed sent into a Components V2 container, Discord's newest format, with a fallback to a classic embed if the message is too long.
  • SQLite storage (since 29 October): data moves from JSON files rewritten in full every 2 seconds to a cyber.db database that only modifies the changed rows. It uses the SQLite built into Node.js (no module to download), imports the old JSON files on its own on first start and falls back to the old storage if Node.js is too old.

Panel security

The panel has no password and no SQL database: no SQL injection is possible. The protections in place:

  • Discord OAuth2 login with a state parameter against CSRF attacks;
  • HttpOnly, SameSite=Lax session cookie, and Secure over HTTPS;
  • displayed text uses textContent or is escaped (against XSS) and a CSP policy script-src 'self';
  • custom header and origin check on every request that changes something;
  • "Manage Server" permission re-checked live on every request;
  • rate limit per IP address (the real IP is read behind the Cloudflare tunnel);
  • HSTS as soon as the panel is over HTTPS;
  • the panel only listens on 127.0.0.1: it is never exposed over plain HTTP on the Internet.

Since 29 October, sessions are also stored as hashes and the log channel can only be changed by an administrator (audit no. 5). Details of tunnel access are in chapter 7.

  • an index.js file at the root that starts src/index.js (the host's panel runs index.js);
  • automatic detection of Pterodactyl: the panel listens on the assigned port and commands are registered at start-up (there is no DEMARRER.bat over there);
  • Node 25 compatibility checked; nothing changes on the PC.

An important rule found along the way: never run the bot on the PC and on the host at the same time, otherwise every command gets two answers.

Step 2 · Updates through a private GitHub repository

Instead of sending a zip after every change:

  1. Enzo creates a private repository on GitHub.
  2. ENVOYER-GITHUB.bat sends the code, refusing to go if a secret or the data/ folder might be included. The .gitignore excludes .env, data/, node_modules/ and zips.
  3. The host reads the repository with a read-only "fine-grained" GitHub token, limited to that one repository.
  4. With the "auto update" option, a simple Restart runs git pull, npm install and restarts the bot.

The .env (bot token, secrets) is never on GitHub: it is created by hand in the host's file manager.

Step 3 · The unreachable panel

The bot was working, but the panel's address gave ERR_CONNECTION_TIMED_OUT. Diagnosis in two steps:

  1. The host's name went through Cloudflare, which only relays the usual web ports (80, 443…), not the assigned port.
  2. Support then confirmed that the machine had no open inbound port.

The bot itself worked because it is the one connecting to Discord (outbound connection). That idea gives the solution.

Step 4 · The Cloudflare tunnel

A Cloudflare tunnel reverses the direction of the connection: the server calls Cloudflare, and Cloudflare then sends visitors of panel.cyberbot.fr to it. Result: HTTPS, hidden IP address, and no port to open.

What was coded (src/utils/tunnel.js):

  • if TUNNEL_TOKEN is present in the .env, the bot downloads the official cloudflared program and starts it;
  • connection over http2 on outbound TCP port 7844;
  • cloudflared gets a minimal environment: it cannot see the Discord token;
  • it is restarted automatically if it goes down;
  • its SHA-256 fingerprint is recorded on first download and checked at every start (and can be pinned to the official value published by Cloudflare);
  • the panel then only listens on 127.0.0.1.

On the Cloudflare side: creation of the cyber-teoheberg tunnel, then a public route panel.cyberbot.fr to the panel's local service.

Two traps met and solved

  • Wrong fingerprint: the PC's .env contained the fingerprint of the Linux version of cloudflared while the PC downloads the Windows version. Security blocked the start, exactly as planned. Setting the official fingerprint of the Windows version was enough.
  • localhost to IPv6: on Windows, localhost was translated to ::1 (IPv6) while the panel only listens on IPv4. The route was fixed to http://127.0.0.1:3000, and the "Bad gateway" error disappeared.

Step 5 · Cloudflare Access: a lock in front of the panel

Even over HTTPS, a public address can be visited by anyone. Cloudflare Access (free) adds a check before the panel is even shown:

  1. "Panel Cyber" application on panel.cyberbot.fr, 24-hour session;
  2. "Me" rule: Allow only for Enzo's email address;
  3. One-time PIN login method only (code received by email), with "instant authentication";
  4. MFA: a 6-digit TOTP code from an authenticator app (Bitwarden), on top of the email code;
  5. custom team name for the login page.

Cloudflare answers the same way whether the address typed is allowed or not: nobody can guess which one is on the list.

29 October: this lock did its job during the test phase. So that everyone can configure Cyber, the Access application was deleted after an audit of the panel (chapter 8, audit no. 5). Security now relies on the panel's Discord login and on the "Manage Server" permission, re-checked on every request. The application can be recreated in two minutes if needed.

Step 6 · The tunnel from the PC

After the host deleted the server (see chapter 11), the same tunnel was restarted from Enzo's PC, simply by changing the route to 127.0.0.1:3000. The panel is available at https://panel.cyberbot.fr as long as the PC and the bot are on. For a future server, it will be enough to copy the .env with the right fingerprint and point the route to 127.0.0.1:<port>.

Chapter 8

Security and audits

Security was treated as a common thread: five audits in four days, each time with a report ranked by priority, a simple explanation of each flaw, then tested fixes.

The basic rules

  • The .env never leaves the machine: it contains the bot token, the OAuth2 secret, the tunnel token and the API key. It is excluded by .gitignore and the upload scripts block anything that looks like a secret.
  • Private bot repository, public website repository but without any secret.
  • Least privilege everywhere: invite without "Administrator", read-only GitHub token on a single repository, panel limited to 127.0.0.1, cloudflared started without access to the Discord token.
  • No personal contact on the website: contact goes through the Discord support server.

Audit no. 1 · Code and configuration security (26 October)

Starting point: npm audit reported 4 vulnerabilities in Express. They were fixed (Express 4.22.3, 0 vulnerabilities), then all the code was reviewed. 12 flaws fixed:

Flaw Concrete risk Fix
Vulnerable Express dependencies A crafted request could crash the bot (denial of service) Update, npm audit at 0
Roles given automatically without checks (the most serious) An Admin role placed in verification, auto-role, a reward or a role panel made any member an administrator A role with moderation or admin permissions is never handed out automatically, and the person configuring it must be able to give it themselves
@everyone / @here mentions Making Cyber ping the whole server through a tag or a reminder By default, Cyber only mentions members
Invite as Administrator If the token leaked, full control of every server Invite link with only the permissions needed
Session fixation Reusing a known cookie after the victim logs in New cookie at every login, strict state check
Panel without a rate limit Filling up the session memory Limits per IP, idle sessions cleared, global cap
Publishing in any channel Making a panel post in a channel the admin can't see Read and write rights checked
Special keys (__proto__, constructor) Writing anything into the configuration (prototype pollution) Allow list of settings, stronger security headers
/pingip An IPv6 hiding a private address (::ffff:7f00:1) allowed probing the host's network (SSRF) Full detection of private addresses, global limit of 20 pings per minute
/dns Revealing internal addresses Private addresses hidden
/embed Publishing where the moderator has no right to write Rights re-checked at publishing time
Spam (tickets, voice channels, buttons, tags) Creating dozens of channels or clicking in a loop Rate limits and caps

Checked with no problem: /calcul (no eval), automod regular expressions, panel display (text always escaped).

Audit no. 2 · The panel against web attacks (28 October)

Enzo's question: "Are SQL injections possible on the admin login?"

Answer: no, because there is no SQL database and no password. The rest was checked (XSS, CSRF, cookies, session theft, brute force, permissions) and 3 improvements were made:

  • behind the tunnel, every request seemed to come from the same IP: a single abuser could block everyone. The panel now reads the real IP passed on by Cloudflare (only if the request really comes from the local tunnel);
  • a malformed cookie no longer causes an error, and a bot can no longer log real users out by flooding the sessions;
  • HSTS enabled as soon as the panel is over HTTPS.

Audit no. 3 · Global audit (28 October, afternoon)

Bot, panel, website and repositories. No secret leak found (website, Git history, archives). Points handled:

Critical

  1. Since the host's server had been deleted without explanation, every secret that was on it was regenerated (bot token, OAuth2 secret, tunnel token, GitHub token).

Important

  1. No backup of data/, and a damaged JSON file was replaced by an empty one → automatic daily backups (7 days), optional sending to a private Discord channel, corrupted file set aside instead of overwritten, RESTAURER.bat.
  2. Daily challenge that could loop forever if its channel disappeared → disabled after 3 failures with a message in the logs.
  3. cloudflared downloaded without verification → pinned version and SHA-256 fingerprint checked.
  4. Cloudflare Access in front of the panel → set up with an email code and a 2FA app (see chapter 7).

Minor (all fixed): server members cached for 5 minutes, small memory leaks cleaned every 10 minutes, optimised automod, lock on the scheduler, finished giveaways deleted N days after they end (configurable with /config giveaways jours:, Enzo's idea for giveaways lasting more than 30 days), .gitignore added to the website, panel never served over public HTTP without the tunnel, npm audit run at every start, Dependabot and Malware alerts enabled on the private repository.

Backup choice discussed with Enzo: GitHub or Discord? Discord was chosen, because GitHub would have required giving the bot a write token (one more secret to protect), while the data only weighs a few KB.

Audit no. 4 · "I want everything spotless" (28 October, evening)

No serious flaw, and the old command flaws remain closed. 15 small holes fixed:

  1. Quiz cheating: the right answer could be guessed from the buttons' ID (readable with a modified Discord). It is now protected by an HMAC signature with a secret key.
  2. Automod could be bypassed by sending a clean message then editing it: edited messages are now checked.
  3. /userinfo showed everyone the number of warnings: now reserved for moderators.
  4. /suggestion and /rappel could make Cyber write in a read-only channel: blocked.
  5. /dns and /pingip accepted local network names (.lan, .home, .local): refused.
  6. Automod false positives because of accents (banned word found inside a normal word): Unicode word search.
  7. Warning if the log channel is public; @everyone refused for the challenge; double ticket closing; duplicates in /panelroles; /warn numbering; orphan voice channels and tickets cleaned at start-up; bot no longer crashes if the disk is full; backups kept with Docker.

A backup bug was also found thanks to Enzo's feedback: the day's backup was only sent to Discord when it was created. If it had been created before the channel was configured, it was never sent. Now the bot sends it again until it has arrived.

Audit no. 5 · Opening the panel to everyone (29 October)

The question: "Between the website and the panel, is it secure?" Before removing Cloudflare Access, the whole path was re-checked point by point:

Point checked Result
Discord OAuth2 login Anti-forgery state parameter, return accepted only to panel.cyberbot.fr/callback, new cookie after login
Cookies HttpOnly, Secure, SameSite
Rights "Manage Server" and the bot's presence re-checked live on Discord on every request
CSRF and XSS Special header + origin checked, strict CSP, escaped text
Abuse Rate limit per person (real IP read behind Cloudflare), limited sessions
Exposure The panel only listens on the machine itself: only the tunnel can reach it

A single hole found: in the panel, a moderator with "Manage Server" could change the log channel, while the /config logs command reserves it for administrators. They could have redirected deleted messages and tickets to a channel they can see. Fixed: reserved for administrators and the owner.

Along the way:

  • the old preview panel's "weird token login" (Discord token in the address) was removed in favour of a redirect to the real panel;
  • sessions were stored in SQLite as a hash (never the cookie itself), excluded from backups and erased by /mesdonnees;
  • a global leaderboard for the mini-game was advised against: anyone could send a fake score in two seconds.

Final test with another Discord account: passed.

Automod against disguised letters (29 October)

My question: "Could we add a bit of AI to the automod, which can be bypassed with two or three text changes?" Two layers were proposed:

  1. Free (installed): before searching for banned words, the text is "flattened". Invisible characters are removed, stylised letters (𝐜𝐨𝐧, ⓒⓞⓝ), Russian or Greek letters that look like ours and flag letters are turned back into normal letters, and words split by a symbol ("con-nard", "con🤡nard") are joined back together. Tested without false positives on normal sentences like "la mer de glace".
  2. AI (Claude Haiku, about 5 cents per 1,000 messages, with an API key separate from my subscription): it would also understand rephrased insults. I preferred not to spend anything for now. The code is kept aside.

Account and infrastructure protection

  • Two-factor authentication on the Discord, GitHub and Cloudflare accounts.
  • GitHub ruleset on main (no deletion, no force push).
  • SPF and DMARC records that prevent spoofing @cyberbot.fr.
  • Obsolete OAuth2 redirects removed from the Discord portal (an old host address could have been taken over by someone else).
